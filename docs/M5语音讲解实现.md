# M5-11 授权语音讲解

更新：2026-09-24。实现范围是管理员提供、已确认授权的音频讲解，覆盖文章和漫步路线。不调用付费 TTS 或其他外部语音 API，不自动生成或下载讲解素材；服务器存储、流量仍属于现有主机资源使用。

## 用户使用

有可用音频的文章或路线详情会显示“听一段讲解”。用户点“播放讲解”后才播放，可暂停、继续、停止；离开详情页或切到后台会停止并销毁播放器，返回页面不会自动续播。播放失败后可主动重试。

没有配置音频、音频未发布、资料已下架或正文版本变化时，不显示入口。普通用户无需登录，也不请求麦克风或录音权限。

## 管理员导入

### 准备条件

- 已发布的文章或路线；关联地点也须公开。
- 管理员确实拥有公开播放授权的 MP3、AAC 编码 M4A 或 PCM WAV 文件，非空且不超过 **8MB**。
- 在小程序目标设备上检查音质及编码兼容性，听审内容与当前正文、路线节点相符；授权说明填写录制者或授权依据，留在管理记录中。
- 操作员是有权限使用服务器管理命令的人员；`--reviewer` 所指账号须是有效职员，拥有 `narration.add_narration` 和 `narration.publish_narration` 权限。此命令不是面向普通用户的上传接口。

命令模板，示例中的文件、资料 slug 和管理员名须替换为真实值：

```bash
scripts/manage.sh import_narration \
  --content '<文章slug>' \
  --file '/本地授权音频/讲解.mp3' \
  --reviewer '<审核管理员用户名>' \
  --rights-note '<录制者或授权依据>' \
  --reviewed --copyright-confirmed --publish
```

路线把 `--content` 换成 `--route '<路线slug>'`，两个参数只能使用其一。

- `--reviewed` 表示已听审与当前资料一致；`--copyright-confirmed` 表示已确认公开播放授权。缺任意一项会拒绝导入。
- 不加 `--publish` 时保存为待发布记录，不对公众提供；准备发布时使用相同受控命令加 `--publish` 导入正式版本。
- 同一资料发布新音频会在一个数据库事务内撤下旧版本，并保留审核记录；审核信息、源版本和文件不允许原地覆盖。
- 后台“授权语音讲解”支持查询、撤下、按权限删除；只读管理员不能撤下。删除记录或删除对应资料后，原文件在数据库提交后清理。
- 本轮没有导入正式讲解，测试只在临时目录及临时数据库生成无声 WAV。管理员仍需自行提供有权使用的音频。

## 公开服务与版本门禁

| 接口 | 行为 |
| --- | --- |
| `GET /api/v1/narrations/?content=<UUID>` | 当前可用的文章讲解元数据，缺少可用音频时 `data: null`。 |
| `GET /api/v1/narrations/?route=<UUID>` | 当前可用的路线讲解元数据。 |
| `GET /api/v1/narrations/<UUID>/audio/` | 重新检查审核、发布状态和源版本后提供音频；支持单段字节 Range。 |

元数据只包含标题、ID、格式、正文版本摘要及受控播放路径，不暴露审核人员、授权说明、原文件名和存储目录。公开接口不处理登录凭据，已过期的登录状态不会阻止公众收听。

文件放在 `MEDIA_ROOT` 同级的 `private-narration` 目录，文件权限 `0600`、目录权限 `0700`；可在 Django 设置中用 `NARRATION_STORAGE_ROOT` 指定独立目录。存储位置不得处于 `MEDIA_ROOT` 或 `STATIC_ROOT` 内，也不得为该私有目录配置 Nginx 静态公开映射。文件没有直接存储 URL，只能按随机 UUID 通过受控接口读取。

导入检查扩展名及文件结构：WAV 检查 RIFF/WAVE 与 PCM 数据长度，MP3 检查连续音频帧头，M4A 检查音频容器、音频轨道和 AAC 编码标记，拒绝伪装网页、视频轨道和不完整容器。播放服务核对文件长度与 SHA-256；提供 `no-store`、固定音频 MIME、`nosniff`。这些是格式与完整性检查，不替代听审或真实设备解码兼容性测试。

音频审核时记录正文摘要：文章涵盖标题、正文、摘要、分类、来源、模拟标记及关联地点文字；路线涵盖标题、说明、来源、区域、模拟标记、节点顺序和节点/地点文字。上述内容变化，或相关地点不再公开，旧音频就停止提供；更新音频需再次审核导入。客户端每次主动开始或继续播放也会重查元数据。

已经传送到设备的音频片段无法远程收回。服务端撤下和正文版本门禁保证后续请求停止取用；当前已缓冲的片段可能继续到用户停止或离开页面。

## 工程集成

- 新 Django app：`narration`，迁移 `narration/0001_initial.py`。
- `INSTALLED_APPS` 加 `narration`，总路由在 `api/v1/` 下包含 `narration.urls`。
- 详情页注册 `narration-player: /components/narration-player/index`，文章/路线加载后使用：

```xml
<narration-player kind="content" target-id="{{item.id}}" />
```

路线使用 `kind="route"`。组件自己请求可用元数据；不需要向知识模型增加字段，不使用录音、后台音频或自动播放。公共 HTTPS 域名沿用业务接口地址，正式发布前仍须完成目标微信版本的真机兼容性检查。

原生能力核对使用微信团队维护、由文档同步生成的 [API 类型定义](https://github.com/wechat-miniprogram/api-typings/blob/master/types/wx/lib.wx.api.d.ts) 和 [组件生命周期定义](https://github.com/wechat-miniprogram/api-typings/blob/master/types/wx/lib.wx.component.d.ts)：确认 `createInnerAudioContext`、显式播放/暂停/停止/销毁、错误及进度事件和页面隐藏回调。开发者文档网站本轮无法打开，未将其访问失败描述为已验证；可访问的官方类型定义列出 MP3/M4A/WAV 的 iOS、Android 支持。
