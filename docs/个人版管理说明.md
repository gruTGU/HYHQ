# 微信云开发个人版：资料、统计与维护

本说明适用于 `cloudfunctions/hyhqApi` 原生云函数版本。数据保存在 `hyhq_data` 单个集合，通过服务端逻辑集合区分业务。数据库权限须为**仅管理员可读写**，小程序通过云函数的身份验证访问，不能直接改数据库取得管理员身份。

## 1. 启用与访问

管理入口默认关闭。仅部署者在服务端设置下列变量后，名单内账号才能使用：

| 配置 | 含义 |
| --- | --- |
| `HYHQ_MANAGEMENT_ENABLED=true` | 打开管理功能 |
| `HYHQ_ADMIN_USER_IDS` | 已登录平台账号的 UUID，多个值用英文逗号分隔 |

名单使用平台用户 ID，不是昵称、OpenID、前端传入的角色或微信开发者账号。管理员仍须正常登录。每次管理请求重新检查账号是否启用；每次写入在事务内再次检查。注销账号和管理写入更新同一用户文档，避免账号停用后继续修改。

在云开发版的“我的主页”进入“平台管理”。普通用户不显示入口；直接打开页面同样会被服务端拦截。页面离开、切换账号或权限关闭后会清空资料草稿、反馈、统计及维护预览；旧请求不能回填新账号页面。

## 2. 公开资料

首次部署即读取经过整理的公开快照 `data/catalog.json`；无需导入用户数据。数据库中的 `catalog` 覆盖文档优先于快照，撤下标记会覆盖原记录。当前快照包含 38 篇科普、31 条路线、82 个地点，以及明确标注的模拟观测。真实天气由独立天气模块处理，快照不包含天气密钥或用户上传图片。

管理页面支持已有科普、路线、地点的文字、来源编辑，撤下及核对后重新发布；全文编辑不渲染任意 HTML。后端另外支持新增资料、路线节点及地点坐标编辑，移动端暂未提供新增和完整地图编辑表单。区域、站点、指标和数据源暂不提供此页面的管理写入。

公开状态会同时影响详情、地图点位、路线节点、检索结果和 AI 资料上下文。旧收藏与浏览记录保留个人记录 ID，下架对象的标题摘要不再公开。AI 在请求发送前及返回后重新读取资料，资料变化时不保存旧回答。AI 的模拟样本按单一来源、成功批次读取，并带有时间、质量状态和模拟说明；它们不表示实时环境结论。

### 管理 API

所有地址以下列相对路径表示，并返回原项目的 `{data, meta?}` 格式。

| 操作 | 路径与参数 |
| --- | --- |
| 查看权限和版本 | `GET personal-admin/status/` |
| 资料列表 | `GET personal-admin/catalog/{kind}/?page=1&page_size=20`，`kind` 为 `contents`、`routes`、`places` |
| 资料详情 | `GET personal-admin/catalog/{kind}/{id}/` |
| 新建 | `POST personal-admin/catalog/{kind}/`，`{value, publish?, expected_revision}` |
| 修改 / 恢复 | `PATCH personal-admin/catalog/{kind}/{id}/`，`{value, publish?, expected_revision}` |
| 撤下 | `DELETE personal-admin/catalog/{kind}/{id}/`，`{expected_revision}` |

新增默认草稿。科普和路线发布前须填写来源。路线节点必须是同区域公开地点；经纬度需成对、有合法坐标系，示意图坐标需关联同区域底图。服务器拒绝未知字段、重复 slug、非法坐标及越界长度。详情含 `value`、`published`、`deleted`、`revision`；列表在 `meta.revision` 返回版本。

全部修改要求当前 `expected_revision`。若其他管理员已经修改，返回 `ADMIN_REVISION_CHANGED`，页面保留尚未保存的文字并提示刷新核对。禁止自动覆盖或盲目重试。每次事务同时保存修改、修订号和审计，失败时一起回滚。

## 3. 统计与审计

“概览”显示启用账号、公开资料、可见识别记录、反馈、AI 内部用量和此环境天气请求预算。接口为 `GET personal-admin/stats/`。

- 账号仅统计仍存在且 `is_active=true` 的用户。
- 公开资料以快照与覆盖合并后的发布状态为准。
- 识别和评估仅统计 `visible=true` 的记录，并按任务状态拆分。
- 反馈分为待处理、已处理。
- AI 用量按北京时间当天统计预约次数、已记账词元、保留词元；不等于提供方结算金额。
- 天气统计此环境本月和滚动 31 天的预约请求，失败也会计数。多个环境共用凭据时必须统一分配预算，不能各自重复使用 30,000 次上限。
- 页面标明查询时间。统计由多个集合查询得到，并非跨集合的同一时刻原子快照。

反馈接口：`GET personal-admin/feedback/?status=pending|resolved`，以及 `POST personal-admin/feedback/{id}/resolve/`，提交 `{reply, expected_revision}`。答复须为 1–1000 字符；正文仅显示在有权限的管理页面和反馈本人页面。

审计接口：`GET personal-admin/audit/?action=...&kind=...`，支持分页。记录包括操作种类、目标 ID、字段名称、数量、时间和 `actor_ref`。`actor_ref` 是服务端稳定身份摘要的哈希，**不是完全匿名数据**；它可关联同一管理员的多次操作。审计不保存用户反馈正文、文章正文、答复正文、OpenID、密钥或会话令牌。

账号注销时清理收藏、浏览、游览、反馈等本人数据；审计保留用于追查关键操作，且不使用 `owner_id` 关联用户文档，不随普通个人记录清理。运营者应在隐私说明及内部保留制度中说明此用途，并制定审计保留期限。本版本尚未自动删除审计记录。

## 4. 模拟批次维护

“维护”中先设置保留策略，再预览，最后确认执行：

| 参数 | 默认值 | 可选范围 |
| --- | --- | --- |
| 保留天数 `retain_days` | 90 | 30–3650 |
| 每来源/场景保留批次 `keep_successful` | 3 | 1–100 |

接口为 `personal-admin/simulation/retention/`（GET/PUT）、`cleanup-preview/`（GET）、`cleanup/`（POST）。保存策略要求 `expected_revision`；执行要求预览返回的 `fingerprint` 与 `expected_revision`。策略或维护范围变化后必须重新预览。

仅允许项目已知的 `demo-normal`、`demo-missing`、`demo-turbidity` 模拟源与 `hourly-v1` 生成批次。真实来源、不明生成器、日期或范围异常、观测计数不一致的批次均受保护。同时保留每来源/场景最近批次、观测窗口最新批次和每站最新批次。每次最多撤下 20 批。

个人版采用**整批撤下标记**：只为批次保存一个覆盖记录，对应观测立即退出公开页面和 AI 上下文。不会为每条观测复制删除标记，不会删除代码包内的只读快照，也不会因此释放代码包空间。需要减少快照大小时，应重新导出公开快照并重新发布。撤下不等于物理删除私有数据；私有数据由下面的独立维护流程处理。

## 5. 到期私人数据维护

页面读取 `GET management/maintenance/` 展示服务器固定保留策略和近期结果。点击执行后调用 `POST management/maintenance/`，仅提交 `{kind?,limit}`，其中每批 1–20 条；不提供任意集合或任意删除条件。维护运行后展示检查、删除、失败数量，可重复运行继续扫描。

具体规则由服务端 `maintenance.js` 定义：原图、缩略图、上传暂存、会话及账本各自有不同保留期限，当前头像随替换或注销清理。页面不可修改这些隐私保留规则。仅在服务器回报已收到可信平台定时触发的成功执行记录时，才显示自动维护已验证；仅设置配置或手动运行不会显示为定时成功。

## 6. 验证与边界

本地单元及接口适配测试覆盖权限关闭、客户端伪造管理员、账号停用竞态、版本冲突、事务回滚、发布与撤稿、隐私隔离、统计口径、审计脱敏、批次保护及页面异步换号。内存事务测试不能替代微信云环境的实际事务、数据库索引、触发器和账号权限联调；部署后须继续验证。

公开快照导出工具仅允许独立恢复库 `127.0.0.1:55438/hyhq_cloud_restore`，拒绝原环境配置文件，并只导出已发布公开资料与成功模拟批次。它不读取用户表、会话、私人媒体、提供方缓存或密钥。客户端不能上传或执行导出脚本。

## 7. 与原 Django 管理端的功能差距

本轮完成的是个人版的资料、统计、反馈与维护管理，并非整个 Django 管理后台的等价迁移。

| 原管理能力 | 个人版当前状态 |
| --- | --- |
| 科普、路线、地点编辑与撤稿 | 已实现服务端接口及移动端已有资料编辑；新增和完整路线节点、地图编辑表单仍待补 |
| 统一统计、关键资料操作审计、反馈处理 | 已实现上述限定口径；没有迁移 Django 全部管理查询、筛选及导出界面 |
| 已有模拟批次浏览、保留策略与维护预览 | 已实现；维护为批次撤下，不减少源码快照大小 |
| 新模拟批次生成、导入及任务执行历史 | 尚未迁移；当前浏览的是经公开校验的既有快照，不生成新批次 |
| 区域、底图、监测站、指标和数据源管理 | 支持公开读取，尚未提供对应管理写入工作流 |
| 模型登记、版本切换、模型文件管理 | 尚未迁移原管理工作流；原生识别适配不等于完成模型管理 |
| LLM 网关的运行时动态配置、多供应商管理 | 尚未迁移；当前通过部署时服务端配置选择和限制已支持的网关能力，密钥不在管理页面显示或编辑 |
| 用户批量管理、角色分配和完整 Django Admin | 尚未迁移；管理员仅由部署者配置 UUID 名单，客户端不能自行授予权限 |

新模拟批次生成应作为独立后续任务：先设计可分页的观测存储，避免将大量生成记录写成 `catalog` 覆盖；再补生成请求幂等、来源/区域校验、每批和总量预算、分批失败恢复及同原图表的数值验证。不能仅增加“生成”按钮就称完成迁移。本轮未启用或实现新批次生成工具。
