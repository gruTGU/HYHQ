# 微信云开发个人版：原生迁移计划

日期：2026-10-03。用户决定只使用已购个人版，接受重构后端。此计划是云分支的当前实施顺序；旧 C00–C05 是已保存的容器方案，不再作为个人版部署前提。原自建服务器版不改动。

## 架构与约束

`微信小程序 → wx.cloud.callFunction → Node.js 云函数 → 文档数据库 / 私有云存储`。

- 复用小程序页面、业务 API 格式、已发布资料、ONNX 模型与判定规则；重写数据库、登录、文件和任务执行。
- 云函数从服务端微信 SDK 获取身份，业务登录后才建立会话。客户端自报 OpenID、AppID、管理员标志均不可信。
- 数据库与对象存储设置为所有小程序用户不可直接读写；云函数检查用户身份、资源归属和保留期限。
- 已发布科普和路线作为不含个人资料的版本快照，管理修改写入数据库覆盖记录；撤稿立即影响检索和 AI 引用。
- 两类图像模型保持固定校验值；Linux CPU 运行库随函数包部署，权重存放在同环境的私有云存储，由服务端下载、核对散列并缓存。文件净化、权限和任务预算独立验证，不以模拟结果代替真实识别。
- 无常驻 worker。任务由请求创建，再由查询请求事务认领执行；超时后的不确定外部调用保守结算，不自动重复扣费。
- 保留三种明确配置：原 HTTP、自建云托管、个人版云函数。个人版网络失败不回退自建服务。
- 不升级套餐，不开启按量付费或自动续费。实际环境的固定月配额：调用 20 万次、容量 3GB、函数资源 15 万 GBs、函数外网出流量 4GB；这些不是无限免费资源。
- 天气的全项目 3 万次上限继续有效。原本机 100 + 北京 29900 已占满分配，个人版初始预算为 0，重新分配前不调用提供方。

## 下一步顺序与实际阻塞

1. 确认微信登录页协议后，创建真实云版账号，验证收藏、足迹、隐私、图片上传和两个模型；不增加测试身份或绕开登录。
2. 用户确认新密钥存放位置与天气预算调整后，启用真实 AI、天气并核对账本；当前提供方关闭。建议预算为本机 100、北京 28,900、个人版 1,000，总计仍为 30,000；未确认前不变更北京配置。
3. 显式指定管理员后，验证管理操作、审计、保留策略和真实过期清理；再补多账号和手机验收。
4. 持续复测偶发连接问题：曾出现两次约 15 秒超时，后续同类请求在 0.6–0.9 秒成功。已加只在本地显式开启的脱敏诊断；尚未证明超时原因，未延长默认超时或自动重复外呼。

逐项证据见[个人版验证记录](verification/个人版原生迁移本地验证.md)。

## 暂不声称完成的能力

评论与举报继续按既有主体和审核条件关闭；天气订阅继续等待模板、用户主动订阅和实际发送条件；语音不凭空生成授权音频。原 Django 管理后台不能直接管理文档库，PN07 必须单独验收，不能用“前端已打开”代替后台迁移。

本地测试、开发者工具真实云调用、手机验证、外部 API 账单分开记录。任何未测项保留未完成标记，不把个人版称为已全面替代现有服务器。

## 部署遇到的限制与处理

开发者工具的上传请求有 50 MiB 上限；44.816 MiB ZIP 编码后的实际请求为 62,666,295 字节，仍超过 52,428,800 字节限制，不能只比较压缩包大小。已将两份原始模型权重上传到本环境私有存储，函数打包改为仅含运行代码、原生依赖和固定模型声明；打包工具须同时检查编码后的请求尺寸并留出余量。模型声明、代码和依赖不从外部动态下载。
