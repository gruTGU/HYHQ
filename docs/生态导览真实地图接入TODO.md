## 一、先做什么

**保留“生态导览”名称。先完善可核对的真实地点与手动选点，再接一种地图检索和步行服务。** 不同时接入高德、百度两套在线查询；先前“高德优先验证、百度备用”的方向仍可采用，但须完成下文资格、展示许可和实际账号预算核验后才能选定。

现有功能是静态示意图、真实地点列表、管理员编排的漫步路线、资料详情与关联 AI 问答。真实地点已有来源，但现有天气网格坐标、虚构河湖点位和用户自记游览不能直接变成导航坐标、实时环境数据或定位打卡。原 [G01–G06 调研](高德与百度数据接入方案.md) 是历史概览；本云分支按本文 EG01–EG10 顺序实施。

建议首期体验：

1. 手动选择天津或北京，查看经核对的地点列表。
2. 有合格坐标的地点可以在真实地图定位；没有坐标时仍可阅读、收藏和查看来源。
3. 用户主动选择起终点后，才查询步行方案；没有结果时展示地址与自编路线，不画一条直线冒充道路。
4. 用户主动点击“我的位置”后才申请单次定位；拒绝定位仍能完成前述手动流程。
5. AI 先围绕已审核地点资料解释，不自主搜索地图、无限调用供应商或断言某校园、河岸当前可通行。

## 三、地图显示、POI 与路线分别选择

POI 指具体地点，如校门、公园入口和景点；它不是水质传感器。高德、百度可以提供地点查询、地址解析和道路规划，不能替代本项目的 pH、溶解氧、浊度等实际监测来源。[高德产品目录](https://lbs.amap.com/api)、[百度地点检索概览](https://lbs.baidu.com/docs/webapi?title=placev3/guide/webservice-placeapiV3)

| 能力 | 首期建议 | 边界 |
| --- | --- | --- |
| 真实地图显示 | 原生微信 `map` + 已核对且有使用权的自有地点坐标，保留列表模式 | 微信原生底图属于腾讯位置服务生态，不会因接入高德/百度 POI 自动换成其底图；不得遮挡标识和审图信息 |
| 地址与地点查询 | 选一家供应商，限定天津/北京和校区附近；主动提交搜索 | 不扫描全城、不自动爬取 POI、不开放通用地图代理接口 |
| 步行路线 | 独立“步行方案”入口，标明供应商、查询时间、距离与预计时间 | 路线规划不是持续导航；校园出入口、开放时间和施工以实际情况为准 |
| 漫步路线 | 保留现有管理员编排与资料引用 | 不把自编阅读顺序当作供应商实时道路规划 |
| 定位/到访记录 | 定位能力单独验收；首期不做 GPS 到访认证 | 一次定位可有误差，不足以证明历史照片地点或真实到访 |

高德的微信插件和百度的微信 JSAPI 都有专门的接入方式；直接客户端 SDK 通常会带自己的小程序 Key/AK，并有域名、调用配额及隐私要求。本项目优先评估云函数内的 Web 服务查询，以便集中限制本应用的调用，但须核对所选产品允许的应用内展示方式；不能将它包装成对第三方开放的地图 API。[高德微信插件入门](https://lbs.amap.com/api/wx/gettingstarted)、[百度微信步行接口](https://lbs.baidu.com/docs/jsapi?title=wxjsapi/guide/guide/walking)

供应商坐标能转换成功，不代表可以任意跨底图使用或缓存其数据。EG01 应记录本应用展示路径与选定接口对应的许可；官方文档未明确覆盖的组合，通过供应商官方工单核实后再启用。此项不是现在要求额外审批，而是后续开通前需要取得的事实证据。

密钥类型依据：[高德 Web 入门](https://lbs.amap.com/api/webservice/gettingstarted)、[高德小程序 Key](https://lbs.amap.com/api/wx/guide/create-project/get-key)、[百度服务端 AK](https://lbsyun.baidu.com/index.php?title=FAQ-obtainAK)、[百度小程序 AK](https://lbs.baidu.com/docs/jsapi?title=wxjsapi/guide/key)。百度各接口的签名、时间戳及坐标参数须按选定版本实现，不能从其他接口照抄。[百度地点检索参数](https://lbs.baidu.com/docs/webapi?title=placev3/guide/webservice-placeapiV3/interfaceDocumentV2)

云函数官方文档提供公网访问和固定出口 IP 配置；固定出口要求公网访问已开启。同一命名空间下相关函数可能共享出口。**是否在当前微信环境可配置、是否另收费，以这个环境的控制台和账单为准**，不把云托管产品的套餐说明套给原生云函数。没有固定出口证据时，不应将一次观测到的动态 IP 当成永久白名单，也不放宽成任意 IP 来“先跑通”。[CloudBase 云函数网络配置](https://docs.cloudbase.net/cloud-function/function-configuration/config)

拟实现的后端约束：固定 HTTPS 主机与路径白名单、禁止重定向和用户自带 URL、输入长度/区域/半径/分页上限、响应大小上限、有限超时、失败无自动供应商切换；业务身份和全局预算在外呼前核验。日志只记录服务类别、耗时、状态和匿名预算编号，禁止完整 URL、Key/SK/SN、原始坐标与搜索文字；云函数响应不透传带凭据的上游链接。密钥不进入 Git、函数源码包、前端、下载文件或管理查询结果。

## 六、坐标、归因、缓存与位置隐私

### 坐标

- 自有地点保存原始坐标、`coordinate_system`、来源、核对人/时间、精度说明和有效状态。地点身份与供应商临时查询结果分开；供应商 ID 或内容仅在选定产品条款允许的范围保存。
- 原生微信地图、`wx.getLocation({type:'gcj02'})` 与 `wx.openLocation` 使用 GCJ-02。WGS84 天气区域点不能直接用于导航；任何未知坐标系先拒绝显示。[微信定位](https://developers.weixin.qq.com/miniprogram/dev/api/location/wx.getLocation.html)、[微信打开地图](https://developers.weixin.qq.com/miniprogram/dev/api/location/wx.openLocation.html)
- 高德转换接口接收非高德坐标并输出高德坐标，参数顺序是经度、纬度。已有 GCJ-02 不再次转换。[高德坐标转换](https://lbs.amap.com/api/webservice/guide/api/convert)
- 百度不同接口的坐标参数命名和值不完全相同。例如地点检索可请求 `ret_coordtype=gcj02ll`，微信步行 SDK 使用 `gcj02`；某些路线参数顺序为纬度、经度。必须逐接口标记输入/输出，并对天津、北京样本验证，不能统一替换字符串或默认 BD-09 就是 GCJ-02。[百度地点参数](https://lbs.baidu.com/docs/webapi?title=placev3/guide/webservice-placeapiV3/interfaceDocumentV2)、[百度微信步行](https://lbs.baidu.com/docs/jsapi?title=wxjsapi/guide/guide/walking)、[百度坐标转换](https://lbs.baidu.com/docs/webapi?title=geoconv/guide/changeposition)

### 归因与缓存

保留地图产品的 Logo、版权/审图信息及接口要求的来源标识，不截图裁剪、重绘地图底图或隐藏署名。自有科普文字可以按现有资料规则保存；供应商地图、POI、路线不能自动沿用天气的长缓存、导出和离线库方式。两家条款对复制、缓存、脱离服务展示、对外封装均有约束；缓存期限和允许字段必须先有具体产品依据，未知时不持久化供应商响应。[高德服务协议](https://lbs.amap.com/pages/terms/)、[百度服务条款](https://lbs.baidu.com/docs/pcsa?title=law/open/law)

首期仅在当前交互需要的范围使用返回结果，是否允许请求合并、短期内存复用也在 EG01 核对。省请求优先靠主动按钮、防抖、取消迟到结果及预算门控，不靠未经许可的缓存。撤销供应商或停用时，按约定删除其数据，保留自有内容；不能把供应商响应复制进科普正文或 LLM 长期记忆规避许可。

### 微信位置能力

| 能力 | 计划用途 | 开放条件和替代路径 |
| --- | --- | --- |
| `map` | 自有合格坐标的地图展示 | 核实专属 Key、标识与实际手机显示；地图失败回列表 |
| `wx.getLocation` | 用户主动选择当前位置作为起点/附近查询中心 | 类目和接口获批、隐私声明与平台授权齐全；拒绝后仍手选 |
| `wx.chooseLocation` | 后续确有必要时让用户在地图选择起点 | 当前无此业务，不为申请而空加；届时按实际权限核实 |
| `wx.openLocation` | 用户主动打开已核对地点的位置页 | 独立处理成功/取消/失败；不等于已实现本应用持续导航 |
| 连续/后台定位 | 首期不用 | 不申请、不生成轨迹、不用于自动到访判断 |

`chooseLocation` 官方页同样列有位置授权；不能把它当成绕过 `getLocation` 条件的方法。平台隐私授权与业务协议是不同环节，保留必需的系统授权，避免增加无业务必要的重复勾选。[微信 chooseLocation](https://developers.weixin.qq.com/miniprogram/dev/api/location/wx.chooseLocation.html)

服务端只接收当前查询必需的坐标，不存轨迹；起点不写入普通日志、公共记录和 AI 提示词。明确位置发给哪家地图服务，用完清除临时状态；截图或录屏证据隐藏私人地址。校园“可参观”“可穿行”和河岸开放状态只在有可靠来源时展示，否则写明未核实。

  - 仅用户主动查询，限定城市/校区范围，每次最多一页受控结果；有来源，查不到明确为空。
  - 验收：同名校区、输入空白、超长文字、无结果、供应商权限/限流/超额错误均不伪造地点；响应数据保留方式符合 EG01 结论。
  - 回退：关闭在线搜索，继续查询本平台已发布资料；不静默调用另一供应商。
- [ ] **EG08 步行方案（原 G05）**
  - 用户确认起终点后调用一次，显示方案来源、距离、预计耗时与时间；校门选择独立于校园中心点。
  - 验收：三校入口和至少两条公共路线核对；断路/闭门/无方案不造路线，起终点调换正确，GCJ-02/BD-09 不混用；过长折线有明确上限和降级。
  - 回退：关闭道路方案，保留地点地址与自编科普路线，标题明确二者差异。
- [ ] **EG09 隐私、归因与 AI 边界（贯穿全部阶段）**
  - 对照实际发送字段更新隐私说明，保持图面署名；公开资料、第三方临时结果与私人位置分开。
  - 验收：前端包/Git/日志无服务端密钥；私人坐标不进 AI；供应商撤回/缓存过期后内容不继续公开。AI 不给未经核实的实时通行、环境或安全结论。
  - 回退：关闭新场景上下文，清理按许可应删除的第三方临时数据，保留本平台原有资料问答。
- [ ] **EG10 发布验证与运行记录（原 G06，最后）**
  - Android/iOS 各一台，实际身份、授权、网络与提供方联调；记录版本、权限、账单、请求数量、归因、失败和回退结果。

## 八、与北京版本及天气预算的关系

现有 [北京天气部署与回退记录](北京天气版本部署与回退.md) 是 2026-09-21 的历史证据：本机 100 + 北京 29,900 已占满项目天气预算。文档中的旧版本、路径和配额不能视为今日服务器现状，也不能据此在新云环境再独立启用 30,000 次。

未来预算切换应先读取真实环境开关与月/滚动账目，停止需要让出配额的实例外呼并等待在途请求结算，再按**本月及滚动窗口已经消耗的总量**决定新环境剩余上限。保留旧账本/保守预占，不通过新 Key、换环境或恢复旧数据库重置总额度。核对提供方账单后才启用新预算；回退时同样连续记账。该过程由天气专项实施和验证，地图 TODO 不改变其配置。

本地图调研子任务没有 SSH、停止服务、密钥迁移、云资源开通、付费购买或地图真实调用；不据此描述整轮云部署与天气切换状态，这些工作另见[U01–U10 计划](云版真实联通与交互优化计划.md)和[实测报告](verification/个人版原生迁移本地验证.md)。下一步可直接做 EG01 的账号证据整理与 EG02 的自有地点校验，其余阶段按依赖逐项推进。
