## 3. 已完成：画面观察摘要

这部分是 **HYHQ 根据上游最新规划重新实现的适配能力**，并非上游已完成代码的整段搬运。上次已整合的 ONNX 检测链路来源不变。本轮没有把 v2–v5 权重引入 HYHQ 或启用，没有新增推理依赖。

### 用户怎么用

1. 进入河道图像观察，主动上传照片；或从个人记录打开一条已完成观察。
2. 在检测候选下面查看“画面观察摘要”：有效候选框数、框并集占整图比例、九宫格位置分布、置信分数范围。
3. 九宫格把每个框按中心位置计入一格，跨格框也只记一次。它与照片方向一致，不代表地图方位。
4. 未检出、图片质量不足、旧记录尺寸不完整等情况会说明暂不能汇总，不显示看似正常的零污染指标。

### 后端口径

- 既有本人任务列表和详情增加 `observation_summary`，`schema_version=1`。成功任务按已保存结果派生，不读原图、不调用模型或上游服务、不改写原检测结果与规则分；无数据库迁移。
- 仍只接受当前已验证的 `class_id=9` 与 `floating_debris`，最多 300 个候选。有效框必须有限、非空、在原图内，置信分数须在 0–1；未知类别、越界、缺字段等候选不修补、不纳入汇总。
- 面积使用框并集，重叠不重复累计；分母是整张原图面积。候选框数不等于真实物体数，也不换算成实际密度。
- 原图划为三行三列，按框中心计数；中心在分界线上时归入右侧或下方格。置信范围与均值只是模型分数统计，不是正确概率。
- 摘要遵循原任务身份、过期与删除规则；没有额外公开端点，不增加坐标、原图路径或文件地址字段。
- 前端校验摘要版本、数值范围及九格计数总和，遇到不完整或不一致的数据展示不可用说明。

## 6. 已完成：上游验收命令的只读诊断适配

补充日期：2026-09-24。本节对应朋友最新代码中确实新增的 `smoke_assessment.py` 验收用途，是经过约束后的重新适配。与第 3 节基于规划实现的画面摘要分开记录；没有复制其任务创建、全局队列消费、无操作文件锁或生态等级结论。

本地原有 `register_detector` 会登记模型，`activate_detector` 会改开关，`run_assessment_worker --once` 会消费队列，没有等价的纯只读检查命令。现新增：

```bash
scripts/manage.sh check_assessment_runtime
scripts/manage.sh check_assessment_runtime --job-id '<已有任务UUID>'
scripts/manage.sh check_assessment_runtime --manifest '<模型根目录内的manifest.json绝对路径>'
```

默认检查：

- 是否恰有一个激活模型和一套激活规则。
- 登记配置的 manifest 契约与配置摘要是否一致；模型文件路径是否位于允许目录、SHA-256 是否一致、ONNX 图结构及输入输出是否符合现有协议。复用现有 `snapshot_for`、`validate_config`、`verify_artifact`、`validate_graph`、`validate_definition`。
- NumPy、ONNX、ONNX Runtime、Pillow、系统文件锁和子进程限制依赖是否存在；ONNX Runtime 是否提供 CPU provider。
- 模型/媒体目录、锁目录权限、工作进程入口、解释器以及超时和队列配置是否具备基本运行条件。只检查锁的位置，不创建或获取执行锁，不判断正在运行的 worker 是否存活。

默认的 manifest 契约来自已登记配置快照，不扫描或猜测原 manifest 文件位置。显式 `--manifest` 会额外核对模型根目录内的 JSON manifest 与登记摘要是否一致；媒体目录里的文件不能作为 manifest 或模型读取。

指定 `--job-id` 时只读取该已有任务的状态、结果及模型/规则快照，重新检查结果结构、规则结果一致性和画面摘要。只输出状态及摘要聚合，不获取用户、图片、坐标字段，不读图。排队中、运行中、失败、过期或不存在的任务明确报未就绪；结构完整的“暂时无法确认”结果可通过结构检查，但摘要仍显示 unavailable，不变成清洁结论。

输出契约：标准输出是单个 JSON 对象，包含 `schema_version=1`、`status=ready/not_ready`、各检查状态和固定错误码；异常详细文字、文件路径及内容不会进入结果。任何必要检查不通过均以非零退出码 `1` 结束，标准错误只报告固定 `ASSESSMENT_NOT_READY`。未配模型明确返回 `MODEL_NOT_CONFIGURED`。

每次报告都带有 `verification_level=static_configuration`、`inference_executed=false` 和 `queue_consumed=false`。**ready 仅说明本次静态配置及可选历史结构检查通过，不等于实际推理烟测、模型准确率评估或服务器部署验收。** 命令不创建/消费/恢复任务、不修改模型开关或规则、不构建推理 session、不改文件锁实现、不发送外部请求。

本轮 **10 项离线 fixture 测试**通过：验证仅产生 SELECT 查询、不调用登记/开关/锁/队列/推理、配置缺失、校验值与图结构、manifest 差异、依赖缺失、锁目录配置、历史结构与摘要、私有数据不输出、媒体目录拒绝读取。测试只用临时模型和数据库，未对当前业务库或真实模型执行该命令。
