# HYHQ 微信云开发迁移可行性

核对日期：2026-09-25。本文是迁移建议，**本轮没有开通云资源、购买套餐、迁移数据库或修改现有部署**。目前代码仍使用自建 Django 服务。

## 结论

**可以让小程序的业务请求不再依赖 `greatdata.asia`。推荐保留 Django 与 PostgreSQL，把后端容器化，并通过 `wx.cloud.callContainer` 调用。** 不必为了免自有域名重写现有业务。官方当前明确：关联环境中的云托管服务可通过此接口访问，无需在小程序后台配置服务器域名。[微信小程序访问云托管](https://docs.cloudbase.net/run/develop/access/mini)

“免自有域名”指小程序到云后端的调用方式；原有浏览器管理后台、文件访问和第三方接口需要分别处理。小程序备案、类目、隐私说明及具体微信接口权限继续保留核验，迁移本身不能代替这些条件。

## 两条技术路线

| 方案 | 对当前项目的影响 | 建议 |
| --- | --- | --- |
| 云函数 + 云数据库 + 云存储，重组业务 | 需要重组 Django 接口、管理后台、后台任务、事务和权限；图像模型还需单独推理服务 | 可以做，改造范围大，暂不优先 |
| 云托管容器 + PostgreSQL + 私有持久存储 | 保留大部分 Django、业务表和现有接口；集中改请求通道、文件、部署及任务互斥 | 优先验证此方案 |

云托管支持任意语言和框架的容器应用。**当前 CloudBase 已有 PostgreSQL 协议直连能力**，适合事务、复杂 SQL 和连接池；不能再按“云开发只有文档数据库”评估本项目。数据库具体规格、地域、连接地址及网络权限要以账户控制台为准。[云托管概述](https://docs.cloudbase.net/run/introduction)、[连接 PostgreSQL](https://docs.cloudbase.net/database/postgresql/connecting-to-postgresql)

## 按当前代码需要改什么

### 1. 请求与真实用户身份

- 在 `miniprogram/lib/client.js` 增加可切换的云托管传输方式：环境 ID、服务名、路径替代普通请求的业务域名；保留统一错误处理、超时、Bearer 会话和账户切换防串号逻辑。
- 首期可保留现有 `wx.login → 后端校验 code → 签发业务会话`。如果以后使用平台注入的 OpenID，需要验证可信入口及 AppID、正确关联已有用户，不能接受客户端自报 OpenID，也不能信任普通公网伪造的身份请求头。
- 区分产品入口：官方说明，后端自动取得 OpenID 目前适用于**微信云托管**，腾讯云侧云托管尚不提供同样能力。最终选择哪个控制台入口后再落实鉴权；两者不能直接混用配置。[小程序访问范围与身份能力](https://docs.cloudbase.net/run/develop/access/mini)

### 2. 数据与私有图片

- Django 继续直连 PostgreSQL，保留事务、行锁、审核和额度账本。迁移前备份，恢复到新库后比对数量、关联关系和历史记录；为后端创建最小权限账号。
- 不把 Django 的用户表、会话表、AI 记录及预算表开放给小程序直接查询；同时检查云数据库的 HTTP/SDK 访问权限，避免出现绕过后端的入口。
- 当前上传、私有下载及语音播放都依赖 HTTP 文件接口；仅改 `request` 不能完成迁移。需增加云存储上传与“完成上传后校验登记”流程，核对文件归属、大小、真实格式、删除及过期策略。推理前将已授权对象下载到临时目录，处理后及时清理。
- 云存储 SDK 支持上传、下载和临时链接；PG 模式改用 RLS 控制权限，传统模式使用安全规则，两套规则不能直接照搬。私有图片不改为公共读。签名链接在有效期内可能被持有者使用，不能把临时链接当作每次重新校验账户的替代；须限制有效期，并测试注销、删除及缓存行为。[云存储 SDK](https://docs.cloudbase.net/storage/sdk)、[PG 文件访问](https://docs.cloudbase.net/storage/pg/serving)
- 容器本地目录会随实例销毁而清除。可选对象存储改造，也可评估 CFS 挂载保留现有文件路径；CFS 的地域、VPC、权限和费用需另行核实，不能把本地 `backend/var` 直接当永久云盘。[临时存储](https://docs.cloudbase.net/run/deploy/configuring/storage/local)、[CFS 挂载](https://docs.cloudbase.net/run/deploy/configuring/storage/cfs)

### 3. 花卉、河道和 LLM 后台任务

现有花卉与河道任务使用本机文件锁，恢复逻辑也假设只有一个主机持有执行权。直接开启多个云实例，可能把其他实例正在执行的任务误判为中断。

首期建议 API 与后台执行职责分开，图像执行端明确只运行一个常驻副本，两类推理仍共享同一执行锁；模型文件随受控镜像或经哈希验证的存储发布。发布时要停旧执行端、确认已退出再启新端，防止滚动发布暂时出现两个执行端。随后再实现数据库租约与心跳，才允许多实例。LLM 的全局并发、幂等结算及取消恢复也要在云环境重新测试。

云托管支持持续运行，但实例缩到零时不会凭空消费现有数据库队列。要么保留付费常驻执行资源，要么另行实现可靠的事件唤醒与任务投递，不能简单把“后台循环”放进普通请求后期待一直运行。[运行模式与实例回收](https://docs.cloudbase.net/run/deploy/configuring/autoscaling/about-instance-autoscaling)

### 4. 管理后台与其他服务

- **小程序免业务域名，不代表原 Django 管理后台也能直接永久免域名。** 当前官方要求，正式环境通过浏览器直接访问云托管等资源应使用自定义域名；默认域名有测试提示及风控限制。[服务域名说明](https://docs.cloudbase.net/service/introduce)、[默认域名限制](https://docs.cloudbase.net/service/alias)
- 若要完全不使用自有域名，可另做小程序内受限管理页面；过渡期也可保留现有服务器上的管理服务，仅经受控管理通道访问。需要同时设计后台连接新数据库及新文件存储的方式，不能把 Django Admin 简单当作小程序页面打开。
- DeepSeek、和风天气仍由后端调用；密钥放云端环境变量或密钥管理，不进小程序与 Git。天气预算在同一数据库统一结算；迁移双跑时先关闭一侧定时任务，避免两个环境各自消耗完整预算。用户每版块每日额度和供应商账单仍由现有逻辑控制。

## 账号、费用和上线边界

**已核实：** 官方当前有资源套餐、按量与资源点等计费方式。2026-08-31 更新的价格说明中，免费体验环境在小程序发布后有效期会变为上线后第 15 天，长期使用需转付费。不要据旧教程承诺永久免费，也不要把独立微信云托管与 CloudBase 的报价混为一张账单。[CloudBase 价格说明](https://cloud.tencent.com/document/product/876/75213)

**账户待核实：** 当前个人主体小程序的关联账户、可创建的产品/地域、PG 与持久存储可用规格、VPC 能力、常驻资源价格、文件流量、构建与日志费用、支付与余额告警。本轮没有登录控制台确认这些条件，尚不能给可靠月费。

**业务待核实：** 官方“深度合成”类目指引明确仅向非个人主体开放；HYHQ 的现有辅助问答是否需要该类目，要按实际页面、服务范围和微信审核要求确认。迁云不会自动解除原有 AI、评论或订阅提醒的开放条件，云开发平台提供的算法合作材料也不能直接视为自有 DeepSeek 接口的适用材料。[微信云开发在用证明与主体要求](https://docs.cloudbase.net/ai/release/algorithm-filing)
