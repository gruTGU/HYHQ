## 资料检索怎么用

科普智游顶部进入“资料检索”，输入关键词（最多五个，空格分隔），或选分类、植物标签、地点。返回已发布手记、路线、地点的原文片段、完整来源说明、更新时间、模拟标识与内部详情入口。分类/植物标签仅筛选手记；地点筛选还包含经过该公开地点且属于同区域的路线。

- 文章检索覆盖标题、摘要、正文、植物标签和公开关联地点名称；路线检索标题/说明/区域，地点检索名称/说明/区域。
- 多关键词是“同时匹配”，不进行自然语言语义推断。标题命中优先，跨类型分页采用稳定顺序。
- 不保存独立检索历史、不发给第三方、不需要登录、不消耗 AI 或天气额度。
- 没有资料时明确返回 `no_evidence`；不生成实时天气、水质或安全结论。
- 可以打开单份资料，经详情已有 AI 浮窗继续解读。**没有实现多资料自动拼接的生成式 RAG**，不把现有页面上下文称为联网搜索。

公开接口：`GET /api/v1/knowledge-search/`，参数 `q`、`kind`（all/content/route/place）、`category`、`plant_label`、`place`、`region`、`page`、`page_size`（最多20）。只接受已定义且不重复的参数。无检索条件时要求输入或选择筛选。

## AI 天气与来源

生态导览/科普智游新建会话时，用户主动选一个平台已配置的真实天气地点；默认不选，也不根据示范区、定位或首页选择偷偷绑定。识别解读不附天气。服务端保存地点 slug，拒绝任意坐标、主机、提示词和不存在/停用地点。

每轮派发前重新读取当前已发布资料和天气缓存：

- 包含地点、和风天气归因、观测或预报时段、抓取/失效时间。
- 过期、未来抓取、异常时间或过旧现况均扣除数值，只保留明确状态。缺失预警不等于无预警。
- 保持三小时现况上限及观测时间容差；预报不当成现况。具体门禁见 [天气说明](M5天气预报与订阅实现.md)。
- 天气上下文先限制 3500 UTF-8 字节；太长时省略整个气象组件，不切断官方归因。整个公开上下文仍限制 10000 字节，包含历史的完整请求文本仍限制 16384 字节。
- 抓取时间、观测时间和固定失效时点参与修订校验；不加入每秒变化的 age。模型调用前后再核对版本，变化或过期会拒绝保存答案，同时如实保留已产生的 token 用量。
- 历史只携带同一资料版本的成功轮次，历史过长先移除完整的早期问答对。
- 会话列表只返回有界的地点、状态和时间摘要，不反复塞入整份天气预警及归因。

成功回答的来源按钮由服务端实际提供给模型的文章/路线/地点生成，最多八条；不采信模型随口编的链接。访问时再过滤已下架来源。点击进入小程序详情核对。常识补充仍要求模型明确区分；提示词约束和模拟测试不能保证真实模型的每一句话都正确。

## 长回答、失败恢复与用量

保留现有三个板块分别计数、全站请求/token 预算及原输出上限；不因为新功能提高预算或自动续写。完整长 Markdown 原样保存并交给现有渲染器；提供方 `finish_reason=length` 等未完成回答进入明确失败态，不把半段当作完整答案，也不自动再花一次额度。

重复的请求编号只返回同一次结果。失败后用户可重新编辑问题再主动发送，失败与未知计费状态仍记入尝试和全站保守预算。

按 [DeepSeek 官方接口文档](https://api-docs.deepseek.com/api/create-chat-completion/) 保留返回的 prompt/completion/total tokens；有提供缓存命中/未命中 token 时，验证它们之和并保留明细。只收到总量时不编造缓存比例。以下命令只读取本地账本，不调用外部服务：

```bash
scripts/manage.sh llm_usage_report --day 2026-09-24
```

输出提交日（上海时区）聚合、成功/失败/待处理数、实收 token 回执、未知用量的安全预留、缓存明细覆盖数和跨日执行计数；没有用户、问题、回答、上游标识或密钥。`invoice_verified` 固定为 false：**这份报告不是金额账单**。
