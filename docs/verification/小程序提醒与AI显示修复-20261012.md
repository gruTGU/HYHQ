# 小程序提醒与 AI 显示修复 · 2026-10-12

## 本轮范围

修复小程序模拟异常通知、生态导览与科普智游 AI 回答显示、关闭 AI 天气附件、改善每日提醒安排保存反馈。网页版不在本轮修改范围内；本轮未提交或推送 Git。

## 修复与验证结果

### 1. 模拟异常通知

- 根因：订阅消息适配器只允许天气页路径，而模拟提醒使用首页路径。在调用微信发送接口之前，消息就被路径校验拒绝；旧异常分支又将此情况记录为“发送结果待核实”。
- 修复：仅增加首页与已知模拟入口的固定路径白名单；保留对任意路径的拒绝。发送前校验失败明确记录为未发出，不标成未知送达。
- 验证：真实发送适配器、发送次数和幂等处理测试通过。云端部署后，用户于本轮在手机重新主动订阅，已确认收到模拟异常服务通知。
- 旧的未知送达记录未重发，也没有伪造或增加订阅次数。

### 2. 两个 AI 对话入口

- 核查时云端与前端的 AI 功能开关均已开启，既有云端记录包含回答正文；未在开发者工具中重现手机正式版的空白正文，不能把历史问题断言为服务关闭。
- 回答正文改为页面直接解析并绑定原生 `rich-text`，避免依赖自定义 Markdown 组件的延迟初始化；保留受限 Markdown 解析与纯文本回退。
- 接口标记成功但正文为空时，显示可操作的失败提示，不再仅显示“解读完成”。不会自动重复调用供应商。
- 补齐纪实自然志等主题的回答卡片内边距。
- 开发者工具内，分别从生态导览和科普智游的城市入口打开对话，未先选具体地点或文章；两次实际 DeepSeek 请求均返回并显示正文、格式与可核对的资料引用。
- 手机正式版的回答显示仍需新版前端发布后验证；本轮没有替用户提交审核或发布正式版。

### 3. 关闭 AI 天气附件

- 移除天气选择、天气参考展示及随对话请求提交天气地点的逻辑。
- 云端发布策略关闭天气上下文，旧会话保存的天气选项也不再附入后续问题。
- 原有模块提示词、地点/文章上下文与资料检索继续保留；天气首页与预约提醒不受此开关影响。

### 4. 每日提醒保存反馈

- 保存中显示“正在保存”；仅在服务端确认保存后弹出成功提示，并在每日安排按钮下显示持久反馈。
- 错误、暂停和提醒次数补充反馈放回对应区域，避免落在下方手动预约区域；切换时间/页面/账号时清除旧反馈。
- 实测保存原有城市及时间，成功提示位于按钮下方，按钮文字与左右留白正常；未新增提醒计划或改变原有时间，也未消耗订阅次数。
