## 明确的产品边界

所有活动显示“演示活动”，非场地方公告，不作为真实举办时间或花期依据。全年花季使用每月1日至月底的演示排期，未宣称某地点实际开花、举办展览或对公众开放。目录支持当前进行中和未来366天的演示条目；地图和提醒只取当前/未来30天。

按用户本轮追加要求，活动预约复用现有“预约提醒”一次性模板及共享提醒次数池。未来活动默认在开始日期的前一天北京时间20:00提醒；已过该时间但活动尚未结束的，尽快安排一次。活动订阅前显示预约时间和一次性消耗，次数不足则展示“+1”按钮，由用户主动触发微信授权；拒绝或授权失败不增加次数。登录站内摘要开关本身不自动请求微信授权。

活动、每日天气的授权池只有一份；活动预约预留1次，取消尚未发送的预约归还预留，明确发送失败按原规则处理，发送结果不确定则保留占用且不自动重发。微信平台实际接收结果为准，前端可见次数不是查询微信后台余额。站内摘要继续独立保留，关闭摘要不等于取消已确认的微信预约。

模板内容使用服务端活动资料并前置“模拟”标识；环境反馈仍不发送政府或外部机构。

环境反馈明确显示“模拟上报”：仅保存至本平台授权管理员工作队列，未发送政府部门、环保热线或其他外部机构，不承诺外部受理。花卉候选不具备污染识别能力，河道候选框和图像教学分也不是水质或污染鉴定；环境描述由用户主动填写，管理员人工核对。

用户手填地点标记 `user_supplied:true`；可信地图参考点名称由服务端目录解析，客户端不能伪造地点资料。图片只引用原识别任务缩略图，原任务删除、图片到期或账号注销即停止授权读取。文字反馈可单独删除；删除反馈不会替用户删除原识别记录。

## 接口契约

| 接口 | 用途 |
| --- | --- |
| `GET events/` | 公开演示活动，响应 `items/notice/server_time/nearby_days`；可选互斥 `place_id`、`map_reference_id` |
| `GET event-subscriptions/` | 本人订阅及活动快照 |
| `POST event-subscriptions/` | `{event_id}`；预留共享次数并创建单次微信提醒，重复幂等，结束/未知活动拒绝，缺次数返回 `SUBSCRIPTION_CREDIT_REQUIRED` |
| `DELETE event-subscriptions/:eventId/` | 仅取消当前账号订阅，未发送预约归还预留次数 |
| `GET/PATCH event-notifications/` | 查询 `enabled/prompted` 或更新 `{enabled:boolean}` 站内提醒偏好（用户选择后记为已询问） |
| `POST event-notifications/claim/` | `{login:boolean}`；仅启用站内提醒且有今日/近期活动时返回 `should_show/items`，优先已订阅活动、按北京时间日期事务领取；登录不能绕过关闭偏好 |
| `GET environment-reports/context/` | `task_kind=recognition或assessment&task_id=UUID`；本人任务摘要、缩略图引用和已有反馈 |
| `GET/POST environment-reports/` | 本人分页记录；提交 `task_kind/task_id/description`，再提供 `location_text` 或可信地点 ID |
| `DELETE environment-reports/:id/` | 本人删除反馈 |
| `GET personal-admin/environment-reports/` | 授权管理员分页队列 |
| `POST personal-admin/environment-reports/:id/resolve/` | `{reply,expected_revision}`；答复并写审计，旧版本或相同答复拒绝重复处理 |
| `environment-reports/:id/photo/` | 由原有 `cloud-files/download/` 分片桥读取的受控缩略图地址，非公开图片 URL |

新的逻辑集合为 `event_subscriptions`、`environment_reports`、`event_delivery_receipts`，沿用当前管理员私有物理集合。提醒偏好、每日弹窗领取日期和记录计数位于用户文档。私人写入事务核对当前活跃账号，和注销互斥；环境上报每日最多创建10条（北京时间），删除不退还当日次数，照片质量不足任务不接受上报；上报以账号+任务生成稳定 ID，相同内容重试复用，内容不同时返回409，不悄悄覆盖。管理员仍沿用原配置、授权、审计和版本号。

## 微信活动提醒后端复核与已知边界

本轮追加云发布标识为 `wechat-event-reminders-20261019`。`event-reminders.js` 只向原有 `weather_subscription_pools` 预留一次授权，和每日天气共用 `reserveCredit`；没有第二份次数账本。活动任务进入原有 `weather_reminders` 队列，复用可信五分钟定时器、事务发送锁、最终账号/订阅检查以及发送结果处理。活动消息不依赖天气服务，模板前置“模拟”活动标题和地点，两个时间字段分别为实际活动开始、结束的北京时间。

每场活动只发送一次。取消未发送预约归还原池预留；已开始发送不可撤回，`sent`/`unknown` 不因取消与重新订阅而重发。`event_delivery_receipts` 仅保存防重复终态，不计算次数；活动结束90天后可清理，避免月度活动的发送任务在30天历史清理后再次推送。注销先删除发送任务，再清理收据和同账号共享池。天气列表有界翻页越过活动任务，保留包括旧无类型字段在内的天气记录。

**已知边界：共享次数是本地估计，并非微信后台余额。** 保留原有 `43101` 拒绝后的保守代际作废规则：若旧请求等待平台答复时，用户新授权的 `+1` 已被另一预约预留，旧请求随后收到 `43101`，该新预留也可能失效并少计一次。不会自动返还可能已被平台消费的次数，也不会重复发送；用户需再次主动授权。这一极端并发场景有回归测试确认不会超发。本轮不扩展共享池协议或伪造补偿授权。

新增云端活动提醒专项覆盖北京时间跨年/闰年、迟订安排、共享池不足与真实授权回调契约、并发幂等、天气/活动竞争一个额度、取消与重订的旧发送锁、发送中取消、未知结果占用、明确失败重试、`43101` 并发、活动长期防重收据、清理、账号注销和可信定时器。样式采用单类选择器，保持隔离河道组件既有检查，不放宽测试规则。
