# M5 本机 DeepSeek 实际联通验证

## 结果

2026-09-24，在本机已启用的 API 服务与 LLM 工作进程上完成 **2 轮真实 DeepSeek Flash 问答，2 轮均成功，没有重试**。接口、来源、上下文、多轮记录、Markdown 结构和用量核对共 **26 项断言通过**。

本轮使用现有网关与凭据，不修改环境变量、模型输出上限、日预算或功能开关。正式服务器、微信发布及微信订阅发送不在本次验证范围内。

安全的详细结果保存在本机忽略目录 `.runtime/m5-return/deepseek-report.json`，临时测试运行清单保存在同目录 `deepseek-fixture.json`，文件权限为仅当前用户可读写。报告不含 API Key、Bearer 凭证、提供方请求 ID 或其他用户对话。

## 实际链路

1. 检查本机开发登录、DeepSeek 环境门禁和管理网关均已启用，确认两次保守预留在原日预算内。
2. 通过本机开发登录入口创建唯一临时测试用户。使用已发布的公开文章《雏菊类：先观察花的正面》，创建 `learn` 会话，显式绑定天气地点 `tianjin`，不附图片。
3. 首轮仅询问文章中的拍摄记录方法，要求 Markdown 二级标题和两条短列表。
4. 首轮成功后，第二轮追问上一轮第一条的具体拍法，并要求仅使用有效天津天气缓存，说明来源和时间。每个问题只提交一次；本轮没有未知失败或自动重试。
5. 轮询本机回合状态，检查真实回答、服务端来源引用和用量；完成后清理本轮临时用户与会话，保留匿名用量总账。

上游通信使用现有提供方实现的固定 HTTPS 接口 `api.deepseek.com/chat/completions`，使用当前运行中的工作进程处理；没有用替代回答模拟成功。

两条记录均标记已派发、成功、`usage_estimated=false`。回合 API 的回执与对应 `UsageLedger` 完全一致；本地 `llm_usage_report` 验证前后的差值为 2 次派发、2 次成功、2 份有效回执、0 份估算，所有 token 数逐项相符。删除临时用户后再次生成汇总，数值保持一致。

原配置保留为单次最大输出 **600 token**、硬超时 **45 秒**、全站每日 **50 次提交 / 100000 token**。每轮入队预留 `32768 + 600 = 33368 token`，两轮最多保守预留 **66736 token**；最终按有效回执结算 3869 token。预留量用于控制未知用量风险，不是实际消耗或人民币金额。

**本轮未核对供应商金额账单，不估算或宣称实际扣费金额。** 回执只证明此次网关收到并记录了上述 token 用量，账单币种、计费日、单价及其他应用用量应以提供方账单为准。
