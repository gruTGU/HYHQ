## 2. 官方能力与当前方案的差距

1. **云调用仍是可行的接入方式。** `wx.cloud.callContainer` 需要小程序关联环境，并且环境内存在已部署的云托管服务；只有云开发环境不等于容器已经就绪。[官方云调用说明](https://docs.cloudbase.net/run/develop/access/mini)
2. **当前 CFS 路线受到个人版能力限制。** 官方配额制、资源点制表均列出：云托管连接腾讯云 VPC 从标准版起支持；CFS 官方流程要求先启用云托管私有网络并使用同地域 VPC/子网。因此现有个人版不能按当前 CFS 方案直接部署全套后端。[配额制能力表](https://cloud.tencent.com/document/product/876/75213)、[资源点能力表](https://cloud.tencent.com/document/product/876/127357)、[CFS 挂载步骤](https://docs.cloudbase.net/run/deploy/configuring/storage/cfs)
3. **当前所见文档数据库不能替代 Django 的 PostgreSQL。** 官方 PG 模式需在新建环境时选择，传统模式不支持原地转换；此规则来自官方文档，本次没有在该账号上创建或验证 PG 环境。[PG 模式说明](https://docs.cloudbase.net/quick-start/pg-overview)
4. **地域、连接和出口仍需核实。** 官方列出的云托管能力随地域不同；数据库原生连接、持续会话以及 VPC 公网出口还需结合真实资源验证，不能凭套餐名称推定可用。[地域能力表](https://cloud.tencent.com/document/product/876/127357)、[PostgreSQL 连接说明](https://docs.cloudbase.net/database/postgresql/connecting-to-postgresql)、[VPC 配置](https://docs.cloudbase.net/run/deploy/networking/vpc)

普通云函数快速开始可以介绍该产品的基础流程，但不会自动将现有 Django/DRF、原生 PostgreSQL、CPU 推理子进程和持久文件转换成 Node.js 云函数。本轮没有为了完成教程而创建与实际后端无关的示例函数。
