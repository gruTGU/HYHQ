# 微信个人版原生迁移：本地验证与部署边界

验证日期：2026-10-03。当前路线为 **PN 个人版原生迁移**：微信云函数、文档数据库、私有云存储。旧 C01–C05 容器、PostgreSQL、CFS 方案及其测试属于历史备选，不能作为本路线已部署的证明。实施范围见 [个人版迁移计划](../微信个人版原生迁移计划.md)。

## 结论

原生业务云函数已成功部署到已购个人版，开发者工具真实读取公开业务，定时维护入口已实际运行。集合与云存储权限均为小程序用户不可直接读写。真实用户登录、图片上传、云内两个模型、外部天气/AI、管理员及手机验收仍未完成；不能声称全部旧功能已可用。

最新本地完整测试和打包数据见下表。模型对照发生在本机 CPU，云端启动结果单独记录。
本轮未调用真实 DeepSeek、和风天气或其他收费提供方；测试中相关调用为可控替身。天气预算在新云环境默认是 0，必须先重新分配现有项目预算，不能额外增加一份 3 万次额度。

### 已覆盖的关键行为

- **身份与数据隔离**：入口只信服务端微信身份；伪造 AppID、OpenID、管理员字段和定时事件均不能获得权限。登录凭据散列保存并绑定调用者；注销、重注册不重置稳定身份对应的当日预算。
- **公开资料与个人记录**：只返回已发布资料；关键词检索附可核对来源；撤稿影响列表、路线、收藏显示和 AI 引用。收藏、历史、足迹、反馈覆盖归属校验、幂等和并发隐私设置。
- **图片与识别**：图片分块限量、规范化、私有读取、原图与缩略图分别过期；上传认领与发布分阶段保存。已确认云文件编号和删除意图持久化，部分删除失败可以重试；头像固定、替换、账号删除、下载期间清理均有竞态测试。
- **AI 与天气**：任务创建后持久排队，读取时事务认领，同一任务不重复外呼；三板块独立日额度、全站请求与 token 预算、跨午夜、超时和不确定账单保守记账。上下文由服务端公开资料和明确地点的天气缓存组成；过期、未来时间、无来源资料不能当成当前事实。外部 HTTPS 不自动重试、不跟随重定向。
- **管理与维护**：显式管理员及新鲜账号检查、统一统计、变更审计、模拟批次预览与保留策略。维护批次有全局租约、扫描游标和数量上限；完成的用量账目保留 90 天，清理不返还当日额度。

### 公开资料与网关启用前复核

区域 AI 资料曾因短字段和关联项目过多超出上下文限制；现保留主页面和来源、有界缩减补充资料，并用完整服务器资料计算修订号。管理资料详情、列表和保留策略增加读前/读后修订校验，避免并发编辑返回旧内容与新版本号。两项均有修前失败、修后通过的回归。

LLM 启用检查与提供方共享凭据规则：缺失会话摘要密钥或 API Key 格式不合法时提前关闭入口，不先入队扣尝试；已排队后配置失效也不发外部请求。附图资格统一校验 JPEG、2 MiB 上限和有效期，无效图片在新请求入队前拒绝；已有幂等请求仍可重放。历史引用改用请求内目录缓存，30 条历史只读一次目录，下一请求立即识别撤稿；外呼前后仍重新核查完整资料。这些均为本地验证，未启用真实网关。

### 实际 SDK 复核修复

测试加载锁定的 `wx-server-sdk 4.0.2`，只替换请求传输层，没有访问云数据库。它验证真实的 SDK 返回形状、EJSON 序列化、唯一编号创建、事务冲突重试和回滚，并覆盖完整登录、文件发布、注销和 LLM 记账流程。

复核发现并修复了两个内存替身不能充分暴露的问题：不存在文档的真实错误格式与原处理不符；SDK 的嵌套对象更新会递归合并，不能保证清空已经释放的预留项。存储适配现对不存在文档作精确处理，对补丁使用事务内读取和完整替换；集合缺失、鉴权或网络错误仍明确失败，不当作空预算。

后续独立复核新增以下 3 项测试，全部通过：

1. **批量失联 AI 任务恢复**：20 个过期任务逐批恢复，每个恢复事务最多处理 4 个任务，且先独立提交，避免后续额度拒绝把恢复一并回滚。测试在 SDK 传输替身强制每事务最多 100 次操作，验证成功释放预留、尝试次数不返还、未知账单不重复记账。官方限制为单事务最多 100 次操作、30 秒，且不支持事务内 `where` 查询。[官方事务限制](https://docs.cloudbase.net/database/transaction)
2. **图片发布已提交、回执丢失**：重新读取并确认已发布资产；保留原图和缩略图，重复完成请求返回同一资产，不因本地尚未收到成功回执而删除对象。
3. **图片发布结果仍不确定**：返回可恢复的确认中状态，保留暂存文件及编号，交由后续确认、取消或维护处理，不把暂时读不到结果当成可立即删文件的证明。

上述 SDK 替身不模拟云数据库索引、真实权限或平台网络。按当前查询，建议优先评估 `_kind + id`、`_kind + owner_id + 时间字段 + id`、识别列表加 `visible`、管理列表按 `created_at + id` 的非唯一复合索引；历史、足迹分别使用 `viewed_at`、`visited_at`。管理筛选再根据真实查询补索引。官方说明无索引条件查询会全表扫描，并建议复合查询匹配索引；现有证据不能推出“没有自定义索引时所有多条件查询必然失败”。索引是否已建、查询是否实际通过均待控制台验收。[官方查询性能说明](https://docs.cloudbase.net/recipes/optimize-database-query-performance)

## 2. 两个模型的验证范围

五类花卉各取 1 张，河道图片 2 张，后两张分别得到 8、19 个检测框。Node 与旧 Python 对照中，解码 RGB 和模型输入 Float32 逐字节相同，候选分数与检测框记录的数值差为 0；断言另外设置了浮点容差。

**低质预筛仍有已知差异**：Node 在 128 像素缩图使用 bilinear，旧 Pillow `thumbnail` 默认使用 bicubic。临界低对比图片的预筛结果可能不同。主模型的 bilinear 预处理已在上述样本逐字节对照；7 组样本相符不代表全部输入等价，更不代表花卉模型已覆盖所有物种或河道检测能替代实测水质。

实际模型测试发生在本机 CPU。Linux 包的 ELF 架构与依赖已静态检查，**尚未在真实云 Linux 运行**，冷启动、内存峰值与长期稳定性仍待云端验收。

### 性能与失败记录

非小程序身份健康测试冷调用实际耗时 4,242 ms、计费 4,300 ms、最大内存 195.12 MB；随后的热调用 3 ms、计费 100 ms、最大内存 96.85 MB。这只证明函数启动和身份门禁，不是图像模型的云端性能。

最后一次部署后重新编译，首页六项真实云请求全部成功：首次天气配置/健康/区域调用约 4.6–6.0 秒，随后三项约 0.5–0.7 秒。最终包散列与源码校验已记录。

公开资料曾出现两次约 15 秒超时，之后重试成功。开启仅本地诊断后，区域 665 ms、路线 670 ms、文章 857 ms；资料检索 953 ms、无结果 624 ms。尚未复现并定位早先超时原因，不能宣布网络稳定性缺陷已解决。新增目录读取回归确认每请求只读一次资料集合，未盲目延长默认期限或重复调用外部提供方。

诊断须显式设置本地 `cloudDiagnostics:true`；仅记录方法、脱敏路径、不带查询的请求序号、耗时、阶段和受控错误码。不记录正文、账号、会话、请求头或 SDK 原始错误信息，源码默认关闭。`clientDeadline` 只表示前端逻辑期限结束，服务器可能仍在执行；`SDKfailure` 表示 SDK 已返回失败。

开发者工具控制台另有基础库兼容提示：工具 `2.02.2608070`、基础库 `3.7.12`。上述公开业务仍成功返回；本轮未切换基础库或升级工具，不能将该提示视为已解决，后续手机和工具兼容验收需继续核对。

### 上传限制与最终包

首次约 57.2 MiB 包在 26% 报 `Body too large`；第二次 44.816 MiB ZIP 编码后实际请求 62,666,295 字节，超过 52,428,800 字节限制。改为私有模型存储后，代码及 Linux CPU 依赖包成功部署；打包现在同时检查 ZIP 与编码后尺寸，保留余量。最终包的字节量、散列和解包校验见[模型私有存储与部署包](个人版模型私有存储与部署包.md)。

### 定时维护边界

计划每 30 分钟执行一批，单批最多 20 条，并在约 25 秒后停止开始下一项。25 秒是软时间预算，在途云 SDK 请求不能据此保证硬中断。仅服务端 `TCB_SOURCE` 为 `wx_trigger`、服务端环境与私有部署环境一致、维护开关明确启用时才接受自动维护；客户端事件字段不能触发。

已观察该可信入口实际成功执行并记录 `timer_verified_at`，随后恢复每 30 分钟配置；由于还没有真实业务图片，本轮未验证物理删除。每 31 天最多约 1,488 次计划触发，按 512 MB、每次都耗满 60 秒的极端假设约 44,640 GBs；不包含其他调用、重试或测试消耗，实际以控制台账单为准。

过期访问立即拒绝，物理删除随轮转扫描与重试完成，延迟受记录数量和存储响应影响。还存在“云上传已经成功、函数在确认文件编号写入数据库前终止”的异常窗口，后续须补对象库存核对或生命周期兜底，不能声称已完全消除孤立文件。[官方定时触发器配置](https://docs.cloudbase.net/en/cloud-function/timer-trigger)
