# 个人版模型私有存储与部署包

## 部署方式

微信开发者工具上传函数时会将压缩包编码为 Base64。实测 44.816 MiB 的 ZIP 被转换为约 62.67 MB 请求，超过 52,428,800 字节限制。因此不能仅以 ZIP 小于 50 MiB 判断能否上传。

本版本将固定模型权重单独保存到同一云环境的私有云存储。函数包仍携带全部业务代码、CPU 原生运行库、模型声明及第三方许可证；运行库通过随包 Brotli 资源解压到私有临时目录，没有从外部网址下载或运行代码。

| 权重文件 | 字节数 | 固定 SHA-256 |
| --- | ---: | --- |
| `flowers-efficientnet-b0-v1.onnx` | 16,047,581 | `01d132fd6fc189adf636060adbe633de57343977d124590e944150f3084fac8f` |
| `river-eco-yolov8n-v1.onnx` | 12,276,950 | `96fc7178c28f1eb29bae9703f440d6bda9c041433edb3e335691f38a5ee6da6c` |

这两份权重与原 CPU 版本完全一致，没有重新训练、量化或删减类别。建议云存储路径为 `hyhq-models/<文件名>`，维持私有读取权限。实际环境和文件 ID 只保存在忽略的部署产物中。

## 私有配置

由 `scripts/package-personal-function.mjs` 将操作人员提供的 ID 写入部署包内部的 `deployment.local.json`：

- `env`：所属云环境 ID。
- `modelFiles.recognition`：花卉模型的 `cloud://` 文件 ID。
- `modelFiles.assessment`：河道模型的 `cloud://` 文件 ID。

也可由服务端环境变量覆盖：`HYHQ_MODEL_ENV`、`HYHQ_FLOWER_MODEL_FILE_ID`、`HYHQ_RIVER_MODEL_FILE_ID`。目标环境必须与平台提供的 `TCB_ENV` / `SCF_NAMESPACE` 相同。API Key、会话密钥不由这个脚本写入代码包。

## 下载与使用边界

1. 公开健康检查只验证配置及固定模型声明，返回 `artifact_status: configured`，不下载权重；这不代表已完成云端推理验收。
2. 创建识别任务只登记排队，先通过账号、图片归属、每日个人额度及全局额度事务。
3. 查询本人任务并取得全局 CPU 租约后，才使用已初始化的服务端 SDK 获取指定模型文件。
4. 文件名、云环境、字节数和 SHA 必须全部匹配。拒绝 HTTP 地址、跨环境文件、路径穿越、未知模型和错误内容。
5. 模型缓存在临时目录，目录权限 `0700`、文件权限 `0600`；每次读取再次验证 SHA。同一实例并发请求复用一次下载。
6. 下载上限 15 秒，超时的迟到响应不能写入缓存；失败冷却 60 秒。空间不足、损坏缓存或下载失败均停止识别，不使用替代权重。

函数打包脚本要求 ZIP ≤36 MiB，并再次检查 Base64 字节量和请求余量。原生解包流程有路径、文件数量、总字节量、Brotli 输出、空间和完整性限制；不完整目录不被加载。

最终 ZIP SHA256：`104e8e26898bbd88a8f856ac10244585b2b08a3fba0ef21d6514b4c49c8af02e`。

本轮最终产物 ZIP 为 **23,387,589 字节（22.30 MiB）**，预计 Base64 为 **31,183,452 字节**。本机完整解包 6,341 个文件、97,732,219 字节，全部哈希一致；最新 22 个源码、数据及许可文件逐字节一致。此包已通过开发者工具更新到云函数，公开页面已真实返回业务数据；两模型的云端推理仍待登录后验证，不能以包部署成功替代模型验收。

## 本机验证

新增模型存储测试覆盖同环境校验、固定文件名、并发缓存、错误大小/SHA、符号链接、缓存篡改、下载超时、晚到响应、空间不足、失败冷却和真实两权重回环。测试文件：`cloud-native/tests/inference-model-storage.test.js`。

本轮启用真实模型对照后的全量 Node 测试最终为 **225/225**（含目录读取、配置预检、附图资格、上下文裁剪和管理并发版本回归）。内存粗测使用同一 macOS 进程解包旧完整模型包、加载 SDK 与 sharp，再顺序运行花卉和河道模型各一次，不强制垃圾回收，峰值约 338 MiB。ONNX 会话逐次释放，下载缓冲区不作为全局缓存保留；云上已配置 512 MB，若模型实际内存接近上限或发生 OOM，再评估 1,024 MB。此测量不等同于云端最大内存保证。

原有真实 CPU 对照仍使用 5 张花卉样本和 2 张河道样本。模型输入和输出对照记录位于忽略目录 `.runtime/personal-inference-compare/`；两个河道样本分别检出 8 与 19 个受支持候选。Node 的低质量预筛采用 bilinear，旧 Pillow 缩略图采用 bicubic，因此临界低对比图片仍可能有判定差异；不应将样本一致性描述为所有输入的数学等价。

最新包大小、库架构和原生库 GLIBC 要求见 `.runtime/personal-deploy/package-report.json`。本机可以验证解包与固定权重，但 macOS 上不能据此证明 Linux 原生库已成功执行；以实际云函数调用结果为准。
