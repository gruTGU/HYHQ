## 协议联调做了什么

本轮 `scripts/cloud-local-verify.py` 启动真实 Django API、花卉和河道 worker，使用独立 PostgreSQL 和私有目录。`scripts/cloud-local-smoke.mjs` 使用正式云客户端代码，但以明确标注的本地 HTTP 桥接替代微信 SDK。

1. 健康接口可读，开发身份登录关闭；相对分页地址可以继续取下一页。
2. 游客私有接口拒绝访问；超过单块大小的图片上传完成并关联头像，下载得到净化后的 JPEG。
3. 账号切换清除本地私有缓存；另一账号无法读取图片；仅提供伪造微信身份请求头不能认证。
4. 花卉与河道分别通过云文件协议上传，真实 CPU worker 生成结果，本人删除后处理私有资源。
5. 原创测试用静音 WAV 分多块下载，结果字节与源文件一致；公开音频继续校验原发布、审核和版本条件。
6. 异源地址在发网络请求前被拒绝；注销撤销会话。临时用户、文章、授权音频与测试会话随后清理。

前端测试另外覆盖断网/超时、取消、晚到回调、账号隔离、JSON/结构错误、上传重试、缓存上限、下载失败删除半成品，以及云语音停止/离页清理。音频真实手机解码兼容尚未验证。

## 后端与云运行检查

- 上传归属、分块大小/总量/次数、幂等、图片净化、到期、注销级联删除；包含真实 PostgreSQL 并发验证。
- 下载仅允许现有资产/讲解业务路径，每块重新核验权限和文件状态，不提供任意 URL 代理。
- PostgreSQL TLS 选项保留到驱动，重复/未知/错误参数关闭启动且不回显数据库凭据。
- 云生产配置拒绝开发身份、缺失凭据、未确认入口、错误目录与容器根目录冒充持久挂载。
- 真实 PostgreSQL session advisory lock 的互斥、释放后接任和连接终止后失锁；子进程退出、失锁终止、健康状态及 Linux 后代进程回收逻辑有测试。
- 云执行仍限定单实例、单组 worker、先停旧再启新。此锁有故障检测窗口，不等于完整分布式隔离；没有验证可横向扩容。
- 管理后台云入口关闭；访问日志不含查询串、请求头和正文。部署脚本语法及源码检查通过。

## 数据恢复演练的范围

只读使用既有本地 `before-m5.pgdump`，恢复到云测试集群的独立 `hyhq_cloud_restore` 库，再应用本分支迁移。`django_migrations`、`django_content_type`、`auth_permission` 三张系统表允许随迁移变动，其余 **45 张业务表**的旧字段摘要和行数一致。`makemigrations --check --dry-run` 返回无变更。

**这次是数据库恢复及 schema 升级演练，不是完整生产迁移。** 历史私有媒体和音频未随旧备份恢复；真实云迁移必须取得同一时间点的数据库、图片、同级 `private-narration`、模型/规则与必要配置，核对用量、删除/授权、任务和发送状态，禁止用旧备份返还额度或复活已删除数据。

## 复跑方法

原项目留在 `/Users/liu/Documents/ChatGPT/Seoul001`；云副本位于 `/Users/liu/.codex/worktrees/hyhq-wechat-cloud-20261003/Seoul001`。本次只借用已有虚拟环境解释器和 PostgreSQL 二进制，没有给原目录安装或升级依赖；云数据库、模型副本、文件、日志均位于新副本忽略的 `.runtime/cloud-migration/`。

在云项目根目录执行，先准备专用测试 PostgreSQL 连接；不要填现网连接：

```sh
ENV=test HYHQ_USE_SQLITE=0 DATABASE_URL='postgresql://TEST_USER:TEST_PASSWORD@127.0.0.1:TEST_PORT/TEST_DATABASE' \
  LLM_ENABLED=0 QWEATHER_ENABLED=0 HYHQ_PYTHON=/path/to/python scripts/manage.sh test --noinput
node --test miniprogram/tests/*.test.js
node scripts/check-miniprogram-compile.mjs
```

完整本机桥接脚本有固定防误用边界：只在 `127.0.0.1:55438/hyhq_cloud_validation` 使用本地专用角色 `hyhq_cloud_test`，API 端口固定 `18083`，要求当前云副本不存在 `backend/.env`。先创建该独立临时集群/数据库，再准备本地既有模型与有权使用的样本：

```sh
/path/to/python scripts/cloud-local-verify.py \
  --model-root /path/to/copied-models \
  --flower-image /path/to/flower.jpg \
  --river-image /path/to/river.jpg
```

模型目录需包含两份已校验的 ONNX 和对应 manifest。脚本创建明确的模拟种子与临时验证资料，不能对业务库执行。真实云运行需严格生产配置，不能把这里的测试设置搬到云端。
