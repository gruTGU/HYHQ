## 已实现

- Django / DRF 后端、PostgreSQL 迁移和 Django Admin。
- 原生微信小程序五个入口，以及详情、个人记录和隐私说明页；底栏保留文字标签并增加极简图标，中央 AI 识别按钮为上凸圆形，预留底部安全区。
- 开发模拟登录、正式微信登录适配、会话撤销、用户权限和账号注销。
- 登录按钮附近说明“继续注册或登录即同意”，用户协议与隐私说明可点击查看；移除重复协议勾选，保留微信系统授权、主动选图/上传、可选定位和删除/注销确认。
- 受控图片上传、去除元数据、鉴权下载、过期清理与头像管理。
- 示范校园 12 个地点、4 个监测站、3 类可重放模拟场景和 CSV 导入。
- 和风天气：天津市、天津工业大学、天津师范大学、天津理工大学、北京市五个地点的实时天气、空气质量与气象预警；手动选择地点，显示来源、更新时间和缓存状态，与模拟生态观测分开展示。
- 天气外呼白名单、持久用量账本、滚动 31 天附加限制、缓存和失败冷却；本机每月最多 100 次、北京 29,900 次，合计 30,000 次，失败和超时计入额度。热带气旋、海洋和辐照接口不开放。
- 原创静态底图、版本绑定点位、分类列表、按钮缩放与拖动；地区选择在浏览页面间共享。
- 智慧河湖和数据中心：按站点、来源、模拟场景、成功批次与时间窗口查询，图表保留缺失断点，提供统计和明细表。
- 收藏、浏览和游览记录，以及识别任务队列与运行日志。
- 科普分类/植物标签/区域/地点/搜索及分页；文章与地点双向关联，预设路线按公开节点浏览并返回。
- 个人反馈提交、分页、管理员答复与本人删除；个人中心和记录页按会话隔离异步操作。
- 五类花卉模型的训练与评估流程、CPU ONNX 推理、受限工作进程和模型版本管理。
- 候选结果、低分/低图质提示、历史模型版本及五篇关联观察科普。
- 河道漂浮物实验检测、检测框、图像教学规则分、可选河段关联和私有评估记录。
- 独立的河道模型/规则版本管理；与花卉任务共用队列容量和单机推理锁。
- DeepSeek `deepseek-flash` 三板块问答：`recognition`（花卉/河道识别）、`explore`（生态导览及相关环境页面）、`learn`（科普智游）。可使用服务端核验的公开页面资料，或绑定本人识别结果并选择是否附图，支持历史会话与删除。
- 三板块各自限制每账号每日五个成功回合，后端按北京时间执行；前台隐藏额度提示，后台保留用量和全站保护。
- 生态与科普相关页面提供悬浮问答入口；DeepSeek Flash 回答支持标题、强调、列表、引用、代码块和表格等 Markdown，使用本地解析及受限节点渲染，不执行原始 HTML、不请求模型输出中的外链图片。
- 独立 AI 工作进程、环境变量密钥、管理开关、调用与 token 预算、幂等请求、超时和用量记录；新环境默认关闭，现有本机与北京环境已配置并启用外部 DeepSeek。
- 管理统计采用统一的北京时间查询口径，区分当前存量与时间窗口内新增量，并按管理员权限裁剪查询结果。
- 关键操作审计记录操作者、时间和对象等信息，审计页面只读，敏感字段不写入日志正文。
- 模拟批次保留策略、清理预览及签名确认执行；保护真实数据、执行中批次和需要保留的最新观测。当前未开启模拟批次定时自动删除。

识别需要登记并启用模型制品，现有测试环境和北京服务器已经配置。模型权重不提交 Git，没有模型时明确返回 `MODEL_NOT_CONFIGURED`。首版只覆盖雏菊类、蒲公英类、蔷薇属花卉、向日葵类、郁金香类；不区分具体物种或品种，高分也不能保证排除范围外图片。当前 v1 的验证集规则选出阈值 0，不按低分拒识，仅输出候选参考；低图质会显示无法确认。

首页城市天气、空气质量和预警为真实上游数据，大学地点表示周边区域天气；示范校园点位、河湖监测和历史生态图表仍以明确标注的模拟数据为主。真实天气尚未写入历史生态图表，也未加入 AI 问答上下文。生态地图为静态示意图，游览记录由用户主动记录；综合生态指数、真实地图导航和定位核验打卡尚未实现。

## 本地启动

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r backend/requirements.txt
cp backend/.env.example backend/.env
# 默认使用 PostgreSQL，连接配置见 backend/.env。
scripts/dev.sh
```

没有 PostgreSQL 时可用 `scripts/dev.sh --sqlite` 做显式本地开发；正式验收使用 PostgreSQL。管理员通过 `scripts/manage.sh createsuperuser` 创建，后台入口为 `http://127.0.0.1:8000/admin/`。

微信开发者工具导入 `miniprogram/`，按该目录 README 配置 AppID 和后端地址。无需 npm 构建依赖。

识别模型的训练、登记、启用和回退步骤见 [图像推理说明](inference/README.md)。生产环境只需 CPU 推理依赖；训练在开发电脑执行。

河道模型的固定版本获取、登记及独立工作进程启动见 [河道推理说明](inference/river/README.md)。本轮只开放漂浮物一类实验检测；未检出显示不确定，图像规则分不代表水质等级，定位可以跳过。

## 开发顺序

已完成的主要开发批次：M1 快照 → M3 图像识别 → 朋友仓库河道功能整合 → 北京基线内部验证 → M2 核心展示 → M2 科普路线、个人记录与隐私 → L01–L06 外部 AI 解读 → 三板块问答与界面完善 → 真实天气、管理统计与审计、模拟批次维护 → 北京新版部署。远程仓库为 [gruTGU/HYHQ](https://github.com/gruTGU/HYHQ)。

下一阶段优先完成正式登录、HTTPS 和手机验收；再按计划接入真实校园地点与地图、完善真实数据和 AI 的结合、提升现有模型实拍效果。垃圾分类、全站知识库检索、语音讲解等扩展尚未开发。本地 LLM 尚未部署，需要先验证整机资源、质量和延迟。
